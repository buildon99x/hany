## 2. 비효율 패턴 (실측 기반)

### 2.1 Sub-agent 미완료 패턴
D1·D2·E1 모두 파일 수정 완료 후 commit 전에 종료. 원인:
- Sub-agent 자체 컨텍스트/시간 제한
- 마지막 단계(commit·ledger 작성)가 작업 큐의 끝 → 잘림 우선순위
- "i18n 키 추가" 같은 후순위 작업이 미완료 채로 남음 (E1이 정확히 이 패턴)

**비용**: phase당 3-5k 토큰 + 30-90초 wall-time × 3 phase. Orchestrator가 자체 게이트 재실행 → 신뢰-그러나-검증 패턴이 중복 작업화.

### 2.2 Hash-chase amend 루프
D2 commit → ledger amend → hash 변경 → 재 amend → hash 변경 ... 무한 루프 인지 후 stale `793ab8a` 8건 그대로 남김. 영구적으로 부정확한 ledger 참조 발생.

### 2.3 Cold-compile 비용 흡수 부재
D2가 `rav1e` + `openh264-sys2` + `reqwest+rustls` + `wiremock` 4종 동시 추가 → 시도당 5-10분. "3 attempt × 10분 = 30분" 가능성을 사전 예측 가능했음에도 묶음 D+E phase로 작성됨.

### 2.4 중복 게이트 실행
Sub-agent "all gates green" 보고 후 Orchestrator가 동일 `cargo check`/`clippy`/`test` 재실행. Phase당 30-60초 중복.

### 2.5 테스트 직렬화 사전 계획 부재
D1이 `TIMELAPSE_RUNNING` 모듈 static 도입, **테스트 직렬 mutex 동반 X**. 테스트가 11개로 늘어난 E1 시점 첫 race 실패 → Orchestrator가 `test_serial()` + 22-line sed 추가.

### 2.6 i18n 키 phase 끝에 배치
Sub-agent가 i18n 키 추가를 마지막 단계로 두는 경향 → 중단 시 catalog 깨짐. E1이 정확히 이 패턴(Step 9 직전 종료 → catalog 미동기 → `i18n:validate` 차단).

### 2.7 Stop-hook 잡음
"uncommitted changes" 알림이 매 어시스턴트 턴마다 발화. Phase 진행 중에는 무의미하지만 컨텍스트 차지 + 흐름 차단.

### 2.8 Sub-agent prompt 보일러플레이트 중복
A/B/C/D1/D2/E1 prompt 모두 CLAUDE.md 관례(~600자), IPC/State/i18n/Privacy non-negotiable 반복. Phase당 ~2k 토큰 보일러플레이트 × 6 phase = **~12k 토큰 낭비**.

### 2.9 묶음 phase contract 비현실성
D+E 묶음 = 18 인수조건 + 4 신규 heavy dep — 사전 정밀 검증 없이 작성. s2 검토 라운드에서 분할 결정을 내렸어야 함.

### 2.10 PR 리뷰 코멘트 비동기 흡수
Codex/Gemini 리뷰가 phase 중간 도착 → context 차지하지만 즉시 대응 불가 → 별도 트리아주 필요. 본 세션에서 7건 누적.

## 4. 즉시 적용 (E2 진입 전)

1. **A** — Sub-agent prompt 첫 문장에 "commit이 acceptance #0" 명시. 미commit 시 incomplete 반환.
2. **B** — E2 contract에 wall-time ceiling 추가 (예: ≤30분 또는 escalate).
3. **G** — i18n 키를 acceptance #2 또는 #3로 끌어올림.
4. **I** — Orchestrator는 sub-agent 보고 후 `git log + cargo check` 만 확인. 전체 test 재실행 X.
5. **L** — `npm run harness:effort --phase E2 --branch ...` 동작 검증.
